# ОПТП СКО — подразделения

Изменения подготовлены в ветке `feature/fire-unit-filter` для проверки через Pull Request. Ветка `main` и рабочая база Supabase не изменяются.

## Установка

1. Получите ветку `feature/fire-unit-filter` из репозитория и проверьте изменения Pull Request.
2. Проверьте интерфейс локально через HTTP-сервер, сохранив текущую конфигурацию Supabase.
3. На тестовой базе с копией действующей схемы проверьте SQL, RLS и доступ гостя/редактора. Миграция здесь не выполнялась: подключения к PostgreSQL нет.
4. После резервной копии выполните `supabase/migrations/202611060001_fire_units.sql` вручную. Миграция транзакционная; повторный запуск останавливается без изменений. При занятой таблице действует таймаут блокировки 5 секунд.
5. Выполните `supabase/migrations/202611060002_seed_fire_units.sql`: справочник заполнится 27 подразделениями из предоставленного `Список.docx`. Исправлен только пропущенный пробел в «СПЧ-5 УЧС г. Петропавловска»; остальные названия сохранены. Повторное выполнение не дублирует совпадающие названия и не меняет существующие записи или закрепления. Справочник доступен только для чтения клиенту; изменения через SQL Editor.
6. Редактор или администратор закрепляет объект через поле «Закреплённое подразделение» в существующей форме. Старые объекты остаются незакреплёнными. Существующие RLS на объектах продолжают определять права записи; фильтр не является ограничением доступа.

Выбор подразделения показывает закреплённые ОПТП. Ввод в общий поиск переключает на все подразделения; последующий выбор подразделения уточняет результаты. Поиск охватывает название, адрес, район и название подразделения. При отсутствии миграции просмотр существующих карточек сохраняется, запись поля закрепления отключается. Документы и схемы не мигрируются, storage/config.js не меняются.

## Проверки

`node --test tests/units.test.cjs`: фильтрация, незакреплённые старые записи, общий поиск и пустые результаты. Проверка синтаксиса inline JavaScript пройдена. Chromium с имитацией Supabase: выбор подразделения, незакреплённые, общий поиск, поле редактора, ширина 375px и отсутствие ошибок JavaScript — успешно. Рабочая база Supabase, её RLS и загрузка реальных файлов не проверялись.

## Откат

Предпочтителен возврат предыдущего фронтенда с сохранением новых таблицы и поля. Полное удаление схемы после начала закрепления потеряет связи; сначала экспортируйте `id, fire_unit_id` из объектов и весь справочник. До заполнения данных можно в транзакции удалить индекс `optp_objects_fire_unit_id_idx`, поле `optp_objects.fire_unit_id` и таблицу `optp_fire_units`. Не используйте CASCADE. Миграция не меняет существующие документы, схемы этажей, storage и политики объектов.
